01 / CONTEXT

背景与判断依据

基于本地项目

当前目录包含六组中医药公开数据及数据说明，尚未发现应用代码或完整需求规格。你已确认暂无额外硬性要求，按当前项目分析。本报告按单人、有限毕业设计周期、教学研究用途提出建议；单人开发与目标用户为分析假设，验收指标为建议值。

6 组已准备的数据来源
599 条本草典四类核心实体记录
195,211 条TCM-MKG D1～D7 原始记录

599 = 365 味中药 + 112 首方剂 + 84 个证候 + 38 部古籍。195,211 是实体表与关系表的数据行总数，不能视为独立知识实体数。以上为本地文件统计，未表示内容已完成专业校验。

指导教师看什么

需求是否闭合；数据模型与查询是否体现知识图谱；关键决策能否解释；系统与实验能否复现。

产品经理看什么

能否解决“查知识、看关系、找依据”的真实任务；数据是否足以支撑功能；新增功能是否值得占用交付时间。

首版数据范围

建议以本草典四类核心实体及其相关关系作为起步范围，先完成单一来源的完整链路。174 首经典方剂作为补充核对材料；TCM-MKG、语义图谱、功效扩展与古籍大库按功能需要逐步接入。

中药、饮片、中成药、经典方剂应保留类型差异；跨来源同名记录不能直接合并。症状在首版可先作为证候属性，待需要独立查询时再建节点。

本次范围决策：Vastbase、Neo4j、十万级数据和智能问答均不作为当前 MVP 的强制条件。现有说明中的技术与数据用法属于参考建议；如后续任务书新增约束，再调整优先级。数据规模应分别报告实体数、关系数与原始行数。

02 / MUST HAVE

MVP 必须实现

六项核心功能，共同支撑可运行、可解释、可复现的首版。

优先级 P0
  1. STEP 01检索知识输入药名或方名
  2. STEP 02阅读详情查看组成与属性
  3. STEP 03探索关系查看相邻实体与路径
  4. STEP 04核对出处回到来源记录或原文
每项均限定首版边界；验收描述为建议标准。
功能最小实现与验收双视角判断与范围边界
M01数据建模、清洗与导入

定义中药、方剂、证候、古籍及组成、关联、出处关系。保留来源 ID、审核状态与导入批次；校验唯一键和关系端点，输出异常清单。

验收：同一批数据重复导入不增加重复记录；失效引用可定位；原始文件保持不变。

教师：体现数据建模与工程处理能力。

产品：保证检索与图谱共用一致数据。

首版采用可重复执行的导入工具维护数据；不要求六源全融合或自动抽取平台。

M02知识目录与实体详情

四类实体列表及详情页，展示名称、分类、已有属性、关联实体和来源。方剂可查看组成，点击药味进入中药详情。

验收：从列表可完成“方剂 → 药味 → 方剂”的往返；缺失字段明确留空或标记。

教师：展示实体模型如何映射到业务页面。

产品：让用户获得可阅读的知识内容。

按原始资料展示；不补造剂量、功效或出处，不扩展为百科门户。

M03关键词检索与基础筛选

支持名称、已收录别名与关键词查询；按实体类型筛选、分页；提供清晰的空结果与错误状态。

验收：预设名称与别名能命中目标；无匹配时不返回虚构结果；结果可进入详情。

教师：可说明查询设计与索引作用。

产品：缩短用户找到知识的路径。

只使用可核实的别名映射；口语纠错、语义检索和复杂组合条件后置。

M04局部知识图谱浏览

以选定实体为中心展示一跳关系；区分节点类型，显示边名称，支持点击详情、缩放及按需展开。

验收：图中关系与数据一致；节点过多时限制数量并提示，避免页面失去响应。

教师：证明图模型已用于真实查询。

产品：直观看清知识之间的联系。

只展示局部子图，建议初始上限 50 个节点；不制作全量图谱大屏。

M05限定关系查询与解释

提供固定查询入口，例如“某方由哪些药物组成”“某药出现在哪些方剂”“某方关联哪些证候”；展示一至两跳已存关系及文字路径。

验收：至少三类查询可运行；结果中的每条边均能回查；无关系时如实说明。

教师：体现关系查询的设计与实现。

产品：直接回答明确的学习问题。

首版用选项或表单表达问题，不依赖大模型；路径关联不等于诊断或因果结论。

M06来源追溯与证据标识

详情与查询结果关联数据集、记录 ID、原始字段；有原文则展示原文，有书目则展示书目。区分原始记载、编辑整理、自动抽取和规则推断。

验收：演示条目均可定位至本地来源；缺少原文时明确说明，不用书名冒充原文证据。

教师：支撑论文引用、数据质量分析及结果解释。

产品：帮助用户判断信息依据与局限。

保留数据来源与使用说明；“编辑审核”不能显示为“临床验证”。
最小页面集合：检索与列表页、实体详情页、图谱与关系查询页、来源说明页。通过统一页面承载不同实体类型，避免为每类知识重复建设一套界面。

03 / NEXT RELEASE

第二阶段增强功能

MVP 验收通过后，按真实使用价值选择，无需全部实现。

优先级 P1
指导教师建议

围绕已有数据与查询继续加深；新增模块要能解释需求来源和验证方法。

产品经理建议

优先消除查询障碍和维护成本，再考虑用户账户、个性化和展示型功能。

功能建议实现范围加入条件与价值
E01带引用的知识问答围绕已入库知识回答单轮问题，返回检索证据与引用；证据不足时说明无法回答。保留普通检索作为服务异常时的替代入口。数据追溯稳定后加入，降低检索门槛。教师关注引用是否支持回答；产品关注回答是否比直接搜索更省事。若题目明确含“智能问答”，其最小版本应纳入 MVP。
E02同义词与组合检索引入经过核对的症状同义词；增加类别、属性、来源等组合筛选，支持结果排序与命中词提示。基础检索存在漏查或结果过多时加入。以固定查询集比较改进前后命中率，不把语义相近直接当作医学等价。
E03数据覆盖扩展按需要增加 TCM-MKG、语义图谱、功效或古籍片段；保留来源命名空间与映射表，人工确认高价值实体对应关系。新增数据能支撑明确场景，或任务书规定数据规模时加入。保留中成药与经典方剂的区别，避免为了数据量强行合并。
E04可视化知识维护管理员查看导入结果、修改整理层记录、停用错误关系；保留操作记录。写操作需要身份验证与权限限制。出现持续纠错或非技术维护者时建设。首版导入工具足以支撑单人维护；不必预先搭建完整后台权限平台。
E05收藏、历史与个人账户保存条目和查询历史；单机可先用本地收藏。需要跨设备同步时再增加注册、登录和账户数据隔离。学习者反复使用后加入，帮助复习与回访。公开只读查询无需强制登录，账户体系不应阻塞知识浏览。
E06实体对照与路径筛选并排对照两首方剂的组成、两味药的已有属性；支持关系类型和路径长度筛选。用户需要比较学习时加入。教师可分析集合与路径查询；产品可减少多页切换。暂不输出治疗优劣排名。
E07知识统计与结果导出显示分类型实体数、关系数、来源占比；导出当前结果和来源信息，图谱支持静态图片导出。核心查询稳定后加入，为学习整理和答辩展示服务。复用已有统计，避免建设独立 BI 平台或复杂报表引擎。
默认顺序：先优化检索与必要的数据覆盖，再加入问答或知识维护；收藏、对照和导出按剩余时间安排。

04 / RESEARCH OPTIONS

可选创新功能

选一个做完整实验，比同时堆叠多个技术名称更有答辩价值。

优先级 P2
方向最小实验范围双视角价值与评价方法
I01 · 优先考虑基于图谱的可解释检索针对固定学习问题，将直接检索与增加一至两跳关系扩展的检索进行比较；展示候选实体、路径和来源。无需先接入大模型。

教师：基线清晰、变量可控，容易形成实验章节。

产品：补充用户遗漏的关联知识。

评价：固定问题集上的 Recall@5、路径有效率及查询耗时。与 M05 的区别在于验证扩展检索是否改善结果。

I02图谱增强问答在 E01 基础上，把相关子图与原文共同作为回答依据；在相同模型、问题集与生成设置下，对比纯文本检索问答。

教师：检验图谱能否改善回答依据与覆盖度。

产品：更容易解释跨实体问题。

评价：回答正确率、引用支持率、无依据陈述比例及耗时；不以回答长度代替质量。

I03规则推理与证据链选择少量有明确依据的功效关系规则，记录规则版本、前提关系与推导路径；显式知识和推断结果分开显示。

教师：展示规则设计与错误分析。

产品：帮助理解知识如何关联。

评价：专家核对样本的准确率与反例。已有推断数据不能同时充当规则输入和独立测试答案。

I04多源差异与证据对照选择一小组方剂或药物，保留多来源记录，列出名称、组成、属性与出处差异；给出候选映射并由人工确认。

教师：体现实体对齐和数据质量分析。

产品：减少同名异义与错误合并。

评价：人工标注集上的对齐精确率、召回率及错误类型。差异只提示，不自动判定某一来源正确。

建议选择 I01：复用 MVP 已有图谱和来源链路，新增依赖少，实验边界清楚。以上是可用于毕业设计的改进与实验方向，尚未进行文献查新，不能直接宣称学术首创。

05 / OUT OF CURRENT SCOPE

当前不建议实现的功能

这些范围对当前毕业设计的投入回报低，或缺少必要条件。

暂不纳入
功能范围当前不建议的原因替代方案 / 重新考虑条件
N01自动诊断、个体处方与剂量推荐当前数据是知识资料，缺少支持临床产品的病例质量、验证体系与专业责任流程；该目标会显著改变项目定位。展示来源中的知识关联与历史记载。仅在有专业团队、独立验证和明确临床项目要求时重新立项；不能把查到方剂包装成个体用药建议。
N02舌象、面诊、脉象识别现有舌象和脉象主要是文本描述，不能据此认定已有可训练、可评估的图像或传感器标注数据。可先展示文字知识。仅在获得匹配模态的数据、标注和独立测试集，且任务书明确要求时开展识别实验。
N03从零训练中医大模型训练资源、数据治理与评估投入容易超过毕业设计范围，且不直接补齐当前核心流程。问答阶段按需要调用现有模型；只有基线暴露明确问题并有可用训练与测试数据时，才考虑小规模微调。
N04全网采集与全自动知识抽取已经有六组本地数据；持续采集、古籍 OCR、实体识别与自动入库会增加噪声和维护成本，难以保证证据质量。先清洗已下载文件。只有缺少关键实体或关系时，才做单一来源、可人工审核的补充采集。
N05问诊、挂号、药品商城与社交社区引入医生、订单、支付、内容治理等全新业务，偏离知识图谱学习与检索目标。首版聚焦知识工具；待形成独立产品需求与业务资源后另行规划。
N06多端与大型平台配套同时开发原生 App、小程序、复杂多租户后台，或预建微服务集群、实时双库同步和高并发平台，会挤占数据质量与核心功能时间。先交付响应式 Web 与简单部署方案。新增终端、租户隔离或扩容必须由明确使用需求和实测瓶颈驱动；任务书指定的技术除外。
双方共识：指导教师优先保护论文与系统的完整性；产品经理优先保护核心使用价值。当前有数据可展示，不等于适合把相应领域全部做成产品。

06 / ACCEPTANCE & CONTROL

验收与范围控制

下列质量要求与六项 MVP 功能一起交付，不是可延后的装饰。

完成标准
  • 数据可复现提供模型说明、导入方法、实体与关系计数、异常记录报告；重复导入结果一致。数据修正在处理层完成。
  • 功能可验证准备正常查询、空结果、同名记录、缺失字段、关系端点失效等用例；至少三条演示路径可完整回查来源。
  • 边界可控查询输入校验，结果分页与图谱数量限制；外部资料作为文本安全展示。若存在在线写入口，必须实施身份验证与权限控制。
  • 系统可交付提供启动说明、固定演示数据、关键流程测试结果；记录测试环境与响应时间。MVP 的检索和图谱演示可在无外部模型服务时运行。

建议验收口径

建立约 30 个固定用例，覆盖名称、别名、关系、来源与异常场景；核心用例全部通过后再增加功能。可将演示数据规模下常用检索与局部图谱查询的 P95 响应时间不超过 2 秒设为初始目标，并注明硬件、数据量和请求条件；该数值是建议目标，尚无系统实测结果。

按完成条件推进，而非按功能数量推进

  1. 先跑通一条真实链路

    例如从“四君子汤”进入组成药物，再查看关联证候与出处；本地已存在相关记录，实施时仍需核对引用完整性。

  2. 完成六项 MVP 并冻结边界

    补齐数据清洗、异常状态、来源定位、测试与部署材料。若时间不足，先减少数据覆盖和页面修饰，保留核心流程与质量要求。

  3. 选择少量增强功能或一个创新实验

    根据任务书取舍。问答、跨源融合和推理不同时起步；加入新功能时明确需要撤下或延后的工作。

  4. 预留论文与答辩时间

    建议在整体时间中保留约 20%～25% 用于修复、实验整理、论文和演示。团队人数与剩余周期未提供，此处不承诺具体交付日期。

建议冻结的首版范围：一个 Web 系统、一组可核验的核心数据、六项核心功能、完整测试与演示材料。若数据库技术栈未被指定，先采用能同时承载实体检索与关系查询的最小方案；若指定双库，明确各自职责，首版可用可重复批量导入避免实时同步负担。

07 / LOCAL EVIDENCE

本地依据与数据注意事项

可回查
  1. 项目数据集说明：六组来源、建议用途、已知格式问题及使用说明。本文据此讨论候选范围，没有把数据用途建议当作已批准需求。
  2. 本草典字段说明及 关系文件：四类核心实体合计 599 条；关系文件有 12 个关系数组、1,477 个关系记录对象，部分对象含多个目标，不能直接等同于最终图边数量。
  3. 中药、方剂、证候、古籍：本次检查的记录均为 editor-reviewed。现有说明中的 verified 示例筛选条件不适用于这四份文件。
  4. TCM-MKG：本次按制表符解析 D1～D7 合计 195,211 行，D6 存在一条列数不一致记录。若引入大规模数据，先处理格式异常，再统计入库结果。
  5. 语义图谱：本地为 6,952 个节点记录、16,619 个关系记录，节点文件按 GB18030 读取。古籍库的候选片段不应等同于专家确认的标准方剂；功效数据中的显式与规则推断记录应分开使用。
