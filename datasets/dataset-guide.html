1. TCM-MKG 多维知识图谱

出处
Zeng Jingqi、Jia Xiaobin，中国药科大学；Zenodo，2024。
发布页
doi:10.5281/zenodo.13763953
本地目录
raw/tcm-mkg/
许可
CC BY-NC 4.0：允许署名的非商业使用，不适合直接用于商业产品。

有什么

当前下载的是课程设计所需的核心 D1～D7 表和官方说明 PDF，共 195,211 条数据记录。它把中医术语、中成药、中药饮片、药性和 ICD-11 疾病编码连接起来。

文件数据行作用
D1_TCM_terminology.tsv1,810中医术语、同义词、拼音、英文和定义。
D2_Chinese_patent_medicine.tsv8,977中成药主表及给药途径。
D3_CPM_TCMT.tsv11,185中成药与中医术语关系。
D4_CPM_CHP.tsv74,084中成药与中药饮片组成关系，含剂量比例。
D5_CPM_ICD11.tsv69,431中成药与 ICD-11 疾病编码关系。
D6_Chinese_herbal_pieces.tsv6,207中药饮片名称、同义词、拼音、英文和来源。
D7_CHP_Medicinal_properties.tsv23,517中药饮片药性及分类关系。

怎么用

  1. 先把 D1、D2、D6 作为实体主表导入 Vastbase/PostgreSQL。
  2. 再导入 D3、D4、D5、D7，用 CPM_ID、TCMT_ID、CHP_ID 建外键或图关系。
  3. Neo4j 中可把 D2、D6 建为节点，把 D4 建为“中成药包含饮片”关系，把 D5 建为“中成药对应疾病”关系。
-- Vastbase / PostgreSQL 示例；路径必须对数据库服务器可见
COPY tcm_terminology
FROM '/absolute/path/D1_TCM_terminology.tsv'
WITH (FORMAT csv, DELIMITER E'\t', HEADER true);
原始数据问题：D6 第 1,718 行（黄芪）有一个多余的空字段，官方 MD5 仍完全匹配。批量导入前应在处理副本中修正或使用容错解析器，原始文件不要覆盖。

怎么用

  • 前端详情页：直接按 key 或 slug 查找药材、方剂、证候和古籍。
  • Neo4j：实体 JSON 建节点，relationships.json 中各数组名作为关系类型。
  • RAG：把古籍段落、概念文章、医案和双语描述切成文档块，同时保留 key、出处和审核状态。
  • 答辩演示：优先选择 verification.status 为 verified 的记录。
import json
from pathlib import Path

herbs = json.loads(Path("datasets/raw/bencaodian/herbs.json").read_text())
verified = [item for item in herbs if item["verification"]["status"] == "verified"]

3. 174 首经典方剂

出处
Li Yuanbai、Yang Yang，中国中医科学院中医药信息研究所；Zenodo，2026。
发布页
doi:10.5281/zenodo.18222225
本地文件
174 Structured Classical Formulas.csv
许可
CC BY 4.0：允许使用和改编，但必须署名。

有什么

174 首经典方剂的 1,249 条药味记录。字段包括方剂名、英文药材名、剂量、单位和君臣佐使角色。每一行是一味药，不是一首独立方剂。

怎么用

  • 按 Formula Name 分组，重建每首方剂的组成。
  • 作为人工整理的高质量“小金标准”，校验主库中的方剂组成和角色。
  • 用于答辩时展示剂量、单位和君臣佐使，不建议用它承担 10 万级数据量指标。
空值含义：部分药味的 Dose 或 Unit 为空，通常表示传统记载未给出固定剂量或该成分作为辅料使用。

4. 中医语义知识图谱

出处
Li Yuanbai、Yang Yang，中国中医科学院中医药信息研究所；Zenodo，2026，版本 2.0。
发布页
doi:10.5281/zenodo.18173424
本地目录
raw/semantic-knowledge-graph/
许可
CC BY 4.0。

有什么

nodes.csv 包含 6,952 个药物、功效、症状、证候、疾病和病因节点；edges.csv 包含 16,619 条有向关系，如 has_effect、manifests_as、treated_by、includes 和 transforms_to。

怎么用

  1. 把节点的 ID 建成唯一约束，TYPE 作为标签或属性。
  2. 边文件的 source_id 和 target_id 对应节点 ID；首列 LID 为空，可忽略。
  3. 适合 Neo4j 路径查询，例如“疾病 → 证候 → 症状 → 功效 → 中药”。
# nodes.csv 实测为 GB18030；先在 processed 目录生成 UTF-8 副本
iconv -f GB18030 -t UTF-8 nodes.csv > nodes.utf8.csv
编码差异：发布方 README 写的是 UTF-8，但当前 nodes.csv 实际需要按 GB18030 解码；edges.csv 为 ASCII。原始文件哈希正确。

Li Yuanbai 等；中国中医科学院中医药信息研究所；Zenodo，2026。
发布页
doi:10.5281/zenodo.18207410
本地文件
raw/herb-efficacy/herb-efficacy.csv
许可
CC BY 4.0。

有什么

28,415 条“中药—功效”关系，其中 7,824 条为教材直接整理的显式功效，20,591 条为知识图谱规则推理得到的扩展功效。有效字段为药物编码、药物名、功效编码、功效名和功效类型。

怎么用

  • 与语义知识图谱共用药物和功效编码，补充 has_effect 关系。
  • 做严谨展示或统计时先使用 Explicit efficacy nodes。
  • 推理实验可加入 Rule A/B/C/D 扩展记录，但结果必须标明“规则推断”，不能写成原文直接记载。
表结构提示：源 CSV 实际有 11 列，但后 6 列全部为空。导入时只保留前 5 列，不要把空列建成业务字段。

6. 古籍方剂抽取 SQLite

出处
Ya Wang、Qiang Song；Figshare，2017。
发布页
doi:10.6084/m9.figshare.5504941.v1
本地文件
raw/ancient-formulas-sqlite/metadata.sqlite
许可
CC BY 4.0。

有什么

表行数字段与用途
fangzi1,728,995id、herb；每个候选方剂的药物出现记录。
fangzi_snippets259,651fangzi_id、snippet；对应古籍原文片段。
fangzi_article259,651古籍文件名及原文起止位置，覆盖 788 个来源文件。

怎么用

  • 通过 fangzi.id = fangzi_snippets.fangzi_id = fangzi_article.fangzi_id 联查药物、原文和出处。
  • 用于药物共现统计、古籍检索、时间/作者分析，以及带来源引用的 RAG。
  • 先按药名空值、药味数量、片段长度和关键词清洗，再把结果写入单独的 processed/，不要修改原库。
SELECT s.fangzi_id, s.snippet, a.article,
       group_concat(f.herb, '、') AS herbs
FROM fangzi_snippets AS s
JOIN fangzi_article AS a ON a.fangzi_id = s.fangzi_id
JOIN fangzi AS f ON f.id = s.fangzi_id
WHERE s.snippet LIKE '%桂枝汤%'
GROUP BY s.fangzi_id, s.snippet, a.article
LIMIT 20;
真实性边界：259,651 条是算法从古籍中识别的“方剂候选片段”，不是 259,651 首经过专家审核的标准处方。论文中应明确写明自动抽取、来源追溯和后续清洗过程。

推荐使用流程

  1. 保留原始层：datasets/raw/ 只读，保留 _record.json、README 和原始哈希依据。
  2. 建立处理层：在 datasets/processed/ 中统一 UTF-8、修复已知格式问题、生成稳定主键并记录清洗规则。
  3. 导入 Vastbase：先实体表，后关系表；TCM-MKG D1～D7 已足够提供 19.5 万条主数据。
  4. 导入 Neo4j：优先导入语义图谱，再补充 TCM-MKG D3～D5 和本草典 relationships.json。
  5. 建立 RAG：古籍片段与本草典古籍/医案作为语料，每个文档块必须保留数据集名、文件名、记录 ID 和来源字段。
  6. 做质量校验：用 174 首经典方剂和本草典已审核记录抽样核对结果；显式知识与推断知识分开统计。
