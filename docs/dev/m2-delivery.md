# M2 交付说明：资料检索页面

日期：2026-10-11。上位文档：[spec.md](../../spec.md) §5。批次：`5a76218e52001d45e4bd75e099a38780408e873342a14e5db0c86d7bb7a3008a`。

M2 只改前端，后端接口不变。spec §5.0 的六项决定均按默认做法实施。

## 1. 页面

| 路由 | 内容 |
| --- | --- |
| `/` | 简介与检索。关键词、类型、来源和页码都写在 URL 中，后退和刷新可恢复结果；每项显示命中说明 |
| `/entity/:id` | 页头、别名、属性（含"其他属性"折叠区）、来源中的注意事项、按 `relation_summary` 生成的关系分区、证据分区 |
| `/evidence/:id` | 证据对象（实体或"起点 → 关系 → 终点"）、原始值、来源记录与文件哈希、完整记录、数据集许可 |
| `/datasets` | 每个来源的版本、地址、许可、署名和三项计数 |
| `/stats` | 业务记录总量及算式、按实体类型、按关系类型、按来源、运行状态、完整批次 ID |
| 其他路径 | 页面不存在 |

原首页的"四君子汤关系样例"已删除，`/api/v1/graph/sample` 接口保留。

## 2. 实现约定

- **依赖**：只新增 `vue-router` 4.6.4（精确版本）。锁文件用 npm 11 生成，与原锁文件格式一致，差异只有新增的两个包。
- **请求封装**（`src/api/client.ts`）
  - 解析统一错误体，页面只显示后端 `message`。
  - 网络失败，以及没有错误体的 5xx（如开发代理在后端停止时返回的 500），一律按"服务不可用"处理。
  - 切换页面或重新请求时取消上一次请求，只渲染最后一次结果。
- **批次**：`build_id` 存在 `sessionStorage`（不可用时存内存），之后的请求都带上它，`/stats` 和 `/health` 不接受该参数。公共请求函数在返回数据前核对所有带 `build_id` 的响应，包括统计响应；批次不一致时抛出 409 `snapshot_changed`，由加载器清空该分区数据。先到响应固定批次，异批次的晚到响应既不覆盖批次，也不进入页面。页面顶部显示横幅，用户点"刷新"才会清除批次并重新加载。
- **分页**：每页 20 条；`offset` 上限 10000，最后可达第 501 页，超出时提示细化条件。检索页的页码超出结果范围时（如旧链接），自动替换为最后一页有结果的页。
- **关系分区**：方剂组成、药物反查方剂、饮片、药性四种分区各有专用列，其余用通用列。
  - 冲突边上为 `null` 的角色或剂量显示"⚠ 来源记载不一致"，并附脚注。
  - 没有专用列的边属性（如药性的 `x_rank`）放在行内折叠的"边属性"中。
- **属性显示**：字段配置在 `src/fieldLabels.ts`，按开发库中每种类型 `attributes_json` 的实际键核对过。嵌套对象按"键名：值"列出，超过 4 层才显示 JSON。所有来源文本按纯文本渲染，没有使用 `v-html`。
- **可访问性**：切换路由后焦点移到页面 `<h1>`。表格使用 `<th scope>`，加载和结果区域带 `aria-live`。

## 3. 验证

环境与 M1b 相同：在云端容器中重建本地 PostgreSQL 16.15，用 `prepare_data.py` 和 `import_vastbase.py --engine postgresql` 导入同一批次，再用 `setup_reader.py` 创建只读账号。没有 Neo4j，也没有配置模型。

| 检查 | 结果 |
| --- | --- |
| `npm run build`（含 `vue-tsc`） | 通过 |
| Vite 开发服务，浏览器逐项核对 | 42/42 |
| `vite preview`，同一组核对 | 42/42 |
| 停止后端：五个页面显示"无法连接服务"和"重试"，后端恢复后点"重试"可正常显示 | 7/7 |
| 停止数据库：详情页显示后端的"关系数据库暂时不可用"；统计页仍显示各服务状态 | 2/2 |
| PR #5 评审修正：批次核对、清除类型筛选、页码越界（修正前 7 项失败） | 8/8 |

逐项结果见 [m2-browser.json](../acceptance/m2-browser.json)，固定用例见 [tests/cases.md](../../tests/cases.md)。核对用无头 Chromium 驱动，脚本没有提交（spec §8.1 不引入前端测试框架）。核对的要点：

- **往返链路**：检索"四君子汤"→ 方剂详情 → 组成中的甘草 → 收录甘草的其他方剂（九味羌活汤）→ 一条组成证据 → 证据对象链接回到方剂；浏览器后退可以逐步返回。
- **猪苓汤 → 泽泻**：角色列显示冲突标记。两条证据的原始值分别为"臣"（方剂组成）和"君"（关系文件），说明冲突来自来源本身。
- **甘草（饮片）**："含该饮片的中成药"共 2,278 条、114 页；最后一页（offset 2260）返回 18 条。
- **ICD-11 编码** `1F68.1` 只显示编码；中成药给药途径显示为"口服（Oral）"。
- **深链接**：检索（带参数）、实体、证据、来源、统计五类页面在开发服务和 `vite preview` 中刷新后都回到原页面。
- **异常状态**：不存在的实体和证据、格式不合法的 ID 显示"未找到"；不存在的路径显示"页面不存在"；把 `sessionStorage` 中的批次改成另一个值后出现"数据已更新"横幅，点"刷新"后恢复。
- **窄屏**：390 px 宽度下检索、详情、统计、来源四个页面都没有横向滚动条。

以上结果来自 PostgreSQL 16.15，不是 Compose 中的 PostgreSQL 18.6；在开发机上按[运行说明](../bootstrap.md)启动后端和前端，即可在目标环境复核。

批次响应回归使用 Node 内置测试和现有 Vite 加载器，无新增依赖。在 `frontend/` 运行 `npm test`，覆盖两种响应顺序、同批次请求、无批次的健康响应和服务端 409。本次在 Node 24.20.0 下通过 5/5 项测试；修复前两种异批次响应都未被拒绝。浏览器以可控响应复核 M2-19，两种顺序都不渲染异批次数据，点击刷新后恢复，同批次请求不误报。
