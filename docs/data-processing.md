## 构建与检查

在项目根目录运行，使用 Python 3.10 或以上版本及自带的 SQLite，无需第三方依赖：

```sh
python3 scripts/import_core.py
python3 scripts/audit_core_data.py --check
python3 tests/test_import_core.py
```

导入成功输出 JSON，其中 `database` 为数据库绝对路径，`build_id` 为完整版本标识，`counts` 为实际入库数量，`issue_counts` 为已登记问题统计。`status=built` 表示新快照，`status=reused` 表示已验证并复用已有快照。

| 产物 | 位置 |
| --- | --- |
| 标准化数据库 | `var/releases/<build_id>/kg.sqlite` |
| 发布清单 | `var/releases/<build_id>/manifest.json` |
| 完整问题报告 | `var/releases/<build_id>/report.json` |
| 便于查看的报告副本 | `datasets/processed/<build_id>.json` |
| 最近一次失败报告 | `datasets/processed/last-failure.json`，仅失败时写入 |

失败报告保留最近一次失败记录，后续成功不会将它改写为成功报告；当前结果以命令退出码及具体构建目录为准。数据库本身就是标准化产物，不额外维护另一套 JSON 实体与关系副本。生成目录已加入 `.gitignore`。

可以通过 `--raw-dir`、`--curated-dir`、`--releases-dir` 和 `--processed-dir` 指定测试副本与输出目录；各输入目录结构需与默认目录相同。

## 清洗和合并规则

- 实体按数据集、类型和原始键识别；同名不会被自动合并。保留原始中文名称，搜索字段执行 Unicode NFKC、首尾空格清理和英文大小写折叠。
- 检索文本只拼接名称、拼音、英文名、拉丁名、分类及中英文描述。原始键、网址、JSON 字段名和剂量字段不进入检索文本。
- `source_record` 保留完整原始对象、文件 SHA-256 和文件内 JSON Pointer。`evidence.field_path` 相对于该对象定位，原文摘录逐字匹配原字段。
- 方剂组成和反向的 `herb_in_formula` 合并为同一条有向边，分别保存证据。书目关联同样按三元组去重，不自动断定唯一首出。
- 剂量保持来源字符串，不换算、不推定。缺失值不覆盖已提供值，并在 `missing_claim_fields` 中列明缺失来源；两个非空值不同时，规范化字段设为 `null`，边标记 `conflicting`。
- 组成顺序优先采用方剂数组下标；只有关系文件提供的组成按药物 ID 排序，标记 `position_source=target_id_order`。方剂属性不再重复存放原始 `composition`，应用应读取规范化边。
- `editor-reviewed` 和来源旧枚举 `verified` 映射为 `editor_reviewed`；`draft`、`needs-review` 分别映射到对应状态。未识别值保存原文并映射为 `unknown`，新增警告会阻止生成发布快照。
- 中药引文和古籍原文保存为 `source_quote`，书目关联保存为 `bibliographic`，来源整理字段保存为 `curated`。不把某部古籍中的任意段落自动当作某条组成剂量的证明。

## 可复现性与失败隔离

构建 ID 包含五份核心输入、来源页面快照、字段说明、来源元数据、问题清单、建表脚本、导入器代码的 SHA-256，以及 schema 和转换规则版本。相同输入与代码得到相同构建 ID；修改代码或整理规则会生成新版本。

先在临时目录完成事务和验证，再将目录整体移入发布目录。已有版本不覆盖；重复运行重新计算逻辑内容并检查已有数据库、结构、证据定位与清单后复用。创建时间不参与逻辑内容哈希，不要求两个独立构建的数据库文件逐字节相同。

JSON 损坏、核心源键重复、必填名称缺失、核心关系端点不存在、未知关系类型或未登记警告都会使命令以非零状态退出，并保留已有快照。构建工具不切换在线服务；当前 Web 最小骨架通过私有配置选择已发布的主库批次，见[阶段说明](bootstrap.md)。

## 验证范围

每次构建校验外键、SQLite 完整性、端点类型、所有边的证据覆盖、来源及证据 JSON Pointer、引文原值、清单行数和内容哈希。

可运行验收脚本另外验证真实输入下的独立重复构建、已有快照复用、原始文件哈希不变、四君子汤组成顺序与剂量、猪苓汤冲突、小建中汤多出处、未关联书目引文、两跳查询、重复关系去重、缺失字段合并、坏输入隔离、命令行失败报告及被修改快照的拒绝复用。

这些检查覆盖数据处理与建表，不代表 API、页面或性能测试已完成。来源许可和署名按本地页面快照写入 [数据集元数据](../datasets/curated/bencaodian.json)。
