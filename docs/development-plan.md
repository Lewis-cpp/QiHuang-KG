# QiHuang-KG 开发计划

制定日期：2026-10-04。状态：范围冻结、两源清洗与 PostgreSQL 入库、Neo4j 样例和前后端最小骨架完成；模型按用户安排留空，Vastbase 迁移在最终交付前完成。适用范围：单人毕业设计或课程项目，最终必须满足 **Vastbase + NoSQL + AI + 十万条以上数据**。

实施记录：199,876 条实体与业务关系已导入持久化的 PostgreSQL 18.6 开发库，详见[清洗与入库运行说明](vastbase-import.md)。当前按用户安排先以 PostgreSQL 推进接口、Neo4j、AI 和页面开发，最后迁移到 Vastbase 并重新验收。下文原计划中要求先取得 Vastbase 的依赖顺序据此调整；四项最终交付指标不变。

本计划依据项目描述、当前仓库和本次确认的四项硬性要求制定。[旧范围分析](../project-scope-analysis.html)与[历史架构](architecture-v1.md)中的“SQLite 作为最终存储、AI 与 NoSQL 可选、无数据规模要求”已不适用于最终交付。[v2 架构与数据模型](architecture.md)及[范围冻结](scope-freeze.md)已更新；启动和模型自行连接步骤见[运行说明](bootstrap.md)。

## 1. 目标与验收口径

交付面向中医药学习与文献研究的知识平台，完成“检索资料 → 查看组成与出处 → 探索知识关系 → 自然语言查询 → 带引用的方剂解释”。数据范围覆盖经典方剂、中药，以及明确区分的中成药、中药饮片和相关术语。

| 硬性要求 | 实现安排 | 必须提交的验收证据 |
| --- | --- | --- |
| Vastbase | 作为正式业务主库，保存实体、关系、来源与证据；检索、详情、统计通过实际实例查询 | 产品与版本记录、建表和迁移脚本、导入报告、真实接口查询、索引与事务演示 |
| NoSQL | 采用 Neo4j，承载局部图谱、一至两跳路径及关系探索 | 实际节点和关系、约束和索引、固定 Cypher 查询、前端调用及执行记录 |
| AI | 实现自然语言条件解析和带引用的方剂解释两项功能 | 实际模型调用、结构化条件、数据库查询结果、引用、评测报告和失败处理 |
| 十万条以上数据 | Vastbase 中通过校验、去重的实体与业务关系合计不少于 100,000 条 | 按来源和表分类的计数查询、去重口径、拒收记录、构建版本与输入哈希 |

十万条按“有效业务实体 + 有效业务关系”估算；原始备份、证据副本、日志、导入历史和 Neo4j 镜像不重复计入。同一业务三元组只计一次，重复来源作为证据保留。这个口径应在第一周写入课程验收说明；若任务书实际要求十万个独立实体或单表十万行，必须重新估算，不能用总记录数代替。

AI 必须真实参与理解和生成，固定答案或预存演示不能代替验收。系统输出保持知识检索和资料解释定位，不接收个体病历或生成个体用药方案。

本次按端点检查：D3、D4、D5 分别有 11,184、74,084、69,431 对不同端点，合计 **154,699 对关系**；这三表中引用的中成药、术语和饮片 ID 未发现缺失，D5 编码非空。该结果说明已有数据具备满足数量目标的基础，仍需经过语义映射、质量检查和 Vastbase 实际入库。

第二周必须处理以下事项：

- D6 文件第 1,718 行列数异常：在处理副本中按具体记录修复，保留原行、修复规则及定位；其他未知异常不能按同一规则盲目修复。
- D3 有一对重复端点：比较其字段，生成一条规范化关系并保留双方证据；不同属性按冲突处理。
- 中成药、经典方剂、中药饮片和中药分别建类型；同名不能自动合并，跨来源映射只采用已核对记录。
- D5 仅提供编码时，显示编码，不补造疾病中文名或临床适用结论；D7 药性节点按分类和名称共同确定身份。
- 字符编码、空值、ID 唯一性、端点引用、剂量原值、字段出处均写入可复现检查；原始文件保持不变。

其余数据集先保留：174 首方剂可用于后续对照，语义图谱与药物功效数据按明确需求接入，古籍 SQLite 中自动抽取的候选片段须经筛选才能进入回答证据。首版问答先使用已收录的方剂字段、关系与可定位引文。来源与署名从现有[数据集指南](../datasets/dataset-guide.html)逐项登记，公开交付前核对原始使用条件。

## 3. 技术路线与模块边界

### 3.1 目标结构

```text
Vue 3 + TypeScript + Cytoscape.js
  检索 / 详情 / 局部图谱 / 自然语言查询 / 方剂解释 / 数据来源
                         │
                  FastAPI 单体服务
               ┌─────────┼──────────┐
               ▼         ▼          ▼
           Vastbase    Neo4j      大模型服务
           主数据与证据  图查询     条件解析、证据解释
               │         ▲
               └── 同一发布批次的离线图投影
```

继续使用既有设计中的 Vue 和 Python 后端，复用现有 Python 数据处理能力。本次硬性要求未指定 Spring Boot，首版不同时维护 Java 与 Python 两套后端；如果课程另有语言要求，在第一周冻结技术栈前调整。

| 模块 | 具体职责 | 首版限制 |
| --- | --- | --- |
| 数据处理 | 读取原始文件、标准化、去重、证据映射、质量报告 | 两个核心来源，不自动融合全部数据集 |
| Vastbase 访问 | 实体检索、详情、组成、证据、统计和维护事务 | 使用验证过的驱动及参数化 SQL；单一正式主库 |
| Neo4j 访问 | 局部图、邻接展开、固定一至两跳路径 | 白名单关系和查询模板，禁止用户提交任意 Cypher |
| AI 查询 | 问题转换为结构化筛选条件，由后端生成查询 | 不执行模型输出的 SQL；不支持的条件明确告知 |
| AI 解释 | 基于检索到的字段、关系和引文解释方剂 | 单轮解释、逐项引用，不扩展成通用对话平台 |
| 前端 | 检索、详情、来源、图谱、AI 结果与异常状态 | 不建设医生工作台、多角色账户或全量图谱大屏 |

### 3.2 数据库迁移与双库一致性

复用现有 `entity / alias / edge / evidence / source_record / dataset / build` 的逻辑模型，新增中成药、饮片、术语、编码和药性等类型，补充组成、术语关联、编码映射及药性关系。常用筛选字段根据实际查询建列和索引，不直接依赖原型中的 JSON 函数与 SQLite 触发器语法。

开发阶段已在 PostgreSQL 验证建表、Unicode、参数绑定、事务回滚、外键和唯一约束、文本存储、批量插入、分页、索引及执行计划。最终迁移阶段须在实际 Vastbase 上重新验证这些能力，记录产品版本和兼容模式并确认实际驱动；PostgreSQL 和 SQLite 的结果不替代 Vastbase 最终验收。

Vastbase 是实体、关系和证据的唯一维护入口。Neo4j 保存图投影、稳定 ID、必要展示属性和证据 ID，证据正文从 Vastbase 获取。已有数据 ID 尽量保持，新来源使用独立命名空间；迁移后逐条比较本草典基线中的实体、关系、证据和冲突状态。

首版采用离线发布，不做实时双写：

1. 生成标准化批次及 `build_id`，在暂存区完成导入校验。
2. 维护窗口停止查询服务，备份当前 Vastbase 数据与 Neo4j 图版本。
3. 导入 Vastbase 并重建同批次 Neo4j 投影；对选定关系类型核对节点、边、ID 集合与内容摘要。
4. 两库版本一致且验收查询通过后恢复服务；未通过时保持未就绪状态，恢复上一完整批次。

不假设两库拥有跨库事务。Neo4j 故障时普通查询可继续使用 Vastbase，图功能明确提示不可用；版本不一致时拒绝组合结果，避免显示旧图与新证据。数据增改通过受控离线整理与重建发布完成；若课程要求管理页面 CRUD，再增加单一管理员入口、认证和修改审计，并单独估算工期。

描述中的“宋代、某病证、不含某药”属于组合查询目标。朝代归属、病证词表和方剂出处必须先完成字段映射与覆盖检查；缺字段时明确说明条件尚不支持，不能静默忽略。首版演示优先选择已确认有数据且能手工核对的问题。

传统配伍提示若实施，以来源、规则版本和匹配药对作为结果；未匹配规则仅表示当前规则库未命中，不输出“可安全同用”。现有关系不能直接视作完整的“十八反十九畏”规则库。该增强项可以延期，四项硬性要求不能延期到交付之后。

## 5. 十周实施排期

假设单人、每周 5 个工作日，每日约 5～6 小时有效投入，总计约 50 个工作日。已有数据处理成果计入基础，不重新计算为待开发工作。以下均为估算；实际启动日期、课程截止日期、Vastbase 环境和模型服务尚未确定，因此使用相对周次。

第 9～10 周共 20% 时间用于验证收尾、部署、论文材料和缓冲。每周必须留下可运行产物或可复核报告，不以“研究完成”“界面完成百分之多少”作为里程碑。

当前依赖顺序：**PostgreSQL 环境验证与入库 → 检索和证据 API → 页面与 Neo4j → AI 查询与解释 → Vastbase 迁移及真实环境复验 → 交付**。原十周排期作为工作量参考，Vastbase 专项移到最终阶段。接口稳定后可穿插页面工作，但单人排期不按多项任务同时满负荷估算。

若只有 6～8 周，先删除 P1、全量数据融合、账户和管理页面；压缩页面装饰及非关键统计。Vastbase、Neo4j、真实 AI、十万条有效记录、来源链和基本测试仍须保留。环境获取和许可办理的等待时间不包含在上述开发估算中。

## 7. AI 的实现与评测标准

### 7.1 自然语言查询

链路为“用户问题 → 模型提取条件 → 实体解析与白名单校验 → 参数化查询 → 数据结果”。返回识别出的条件，让用户看清查询实际执行了什么。存在同名实体时先展示候选；无法表达的问题说明支持范围。

第一版支持已落地的字段和少量组合条件，不建设自由 SQL 生成器。模型不能提供任意 SQL、Cypher、文件路径或新的可执行工具。设置结果条数上限和查询超时；输入中的指令以及检索资料中的文本不能改变后端允许的操作。

### 7.2 方剂解释

使用现有主库和图查询取方剂属性、规范化组成边、证候关联与可定位引文，将材料和证据 ID 一并传给模型。图路径用于解释关联，不能从两跳路径自动推出新的治疗结论。角色为空或有冲突时如实说明。

首版按实体与关系检索即可形成带引用的生成链路，不预先引入向量数据库。引用 ID 存在只证明来源可定位，不能证明文字受到支持；还需结构化字段比对与人工评测。完整古籍原文未提供时，不用书名代替原文证据。

### 7.3 评测集与建议目标

建立 20 条开发样本和至少 60 条冻结测试样本，记录问题、支持状态、预期条件或事实、证据和实际结果。以下为项目建议门槛，尚未测得。

| 测试类别 | 测试数量 | 建议验收目标 |
| --- | --- | --- |
| 支持范围内的自然语言查询 | 25 | 执行结果与人工条件查询完全一致的比例 ≥ 90% |
| 方剂解释 | 20 | 引用可定位率 100%；人工逐项审核的事实支持率 ≥ 95% |
| 无依据、歧义、越界与注入请求 | 15 | 不执行未授权查询；关键失败样本全部通过 |

事实支持率为“被引用材料支持的可核查事实项 / 全部可核查事实项”，不能按回答长度计算；无事实输出不能以空分母算作通过。对明确可回答的样本拒答也算未完成。组合药味、剂量、角色和出处若出现编造，作为阻断问题修复。记录失败样本、模型和提示模板版本、生成设置、耗时及实际调用费用，不预设模型必然达到目标。

## 8. 系统验收与风险处理

### 8.1 发布条件

| 方面 | 检查方式 | 发布要求 |
| --- | --- | --- |
| 数据规模 | 在正式 Vastbase 上按来源与实体/关系计数 | 至少 100,000 条有效业务记录，镜像和历史不重复计数 |
| 数据质量 | 唯一键、关系端点、来源定位和重复构建检查 | 无悬空边；每条发布关系可定位证据；重复导入不增量堆积 |
| 核心功能 | 至少 30 个固定用例，覆盖检索、详情、图、证据和异常 | P0 用例全部通过；加载、空值、无路径、截断与错误状态可见 |
| 双库一致性 | 发布版本、节点/边 ID 集合和内容摘要比较 | 选定图投影与主库一致；构建失败或版本错配时不能发布混合数据 |
| AI | 冻结样本评测、引用和权限边界测试 | 达到第 7 节门槛，真实调用可演示 |
| 性能 | 十万条以上数据，单用户及 5 并发分别测量 | 普通检索和局部图目标 P95 ≤ 2 秒；AI 目标 P95 ≤ 15 秒，30 秒超时并提示 |
| 故障恢复 | 主库只读权限、图服务中断、模型失败、恢复演练 | 无越权写入；明确降级；完整批次可恢复 |
| 部署 | 按说明在新环境启动，刷新页面深链接 | 前端、服务和两个数据库可连通；数据与密钥不作为静态文件公开 |

性能测试记录硬件、版本、并发数、快照、请求样本和返回规模。非 AI 查询预热 20 次后分别采样至少 200 次；AI 测量使用评测请求记录真实延迟和费用，另报告样本量。失败与超时必须单列，不能从统计中删除后声称全部满足目标。上述性能数字是目标，正式结果以实测为准。

### 8.2 风险与调整动作

| 风险 | 最早发现时间 | 处理动作 |
| --- | --- | --- |
| Vastbase 环境或驱动不可用 | 第 1 周 | 优先处理真实连接验证；等待期间继续纯数据清洗，环境未通过前不认定主库完成 |
| 数据量口径不同 | 第 1 周 | 核对任务书，重新统计；独立实体数要求不能用关系数冒充 |
| 多源误合并与原始格式异常 | 第 2 周 | 独立命名空间、记录级修复、保留冲突；暂停有问题的映射，不丢失原值 |
| 中文子串检索在扩容后变慢 | 第 3 周初测，第 9 周复测 | 先分析查询、索引和分页；确认瓶颈后再增加专用检索能力 |
| 两库数据不一致 | 第 5 周 | 离线同批发布、版本检测、恢复旧批次；不引入实时双写 |
| 模型编造、误解条件或引用不支持文字 | 第 6～8 周 | 限定字段与材料、实体消歧、引用与事实核对、失败拒答和固定测试 |
| AI 成本或延迟超过预算 | 第 1 周初测，第 6～8 周复测 | 控制材料和输出长度、请求上限；比较实测模型后选择，不取消真实 AI 验收 |
| 功能范围持续增长 | 每周 | 第 8 周冻结范围；优先删 P1/P2，保留最后两周交付时间 |
